# Units

**Prefix.** UNIT.

**Status.** Agreed on 2026-11-11.

**Briefs.** [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units).

## Scope

The units give each run the system of code units in which it computes, from three base units given in cgs, and convert into it the values that declarations name in physical units and the constants that conduction and cooling need, as [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units) decides. They are the frozen dataclass `Units` of the module `mhdpy.infrastructure.units`, which declares the three base units as the parameters of [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters) and offers the conversions. The reading of the base units from the inputs of a run, and the conversion of each parameter by the unit that its declaration names, are left to the parameters, and the values of the constants in cgs to the constants. Named systems of units, such as that of Athena++ for the interstellar medium, are left to the brief that first needs one, as the density of such a system rests on the mass that the brief on equations of state chooses. The units that a declaration may name form a table fixed in stratum 1, to which later briefs add their own, rather than a registry filled as modules are imported, which B5D1 set aside.

The base units $M_0$, $L_0$ and $T_0$ are the code units of mass, length and time, in cgs. A dimension is a tuple of four integer exponents $(a, b, c, d)$, of mass, length, time and temperature, as $(1, 2, -2, -1)$ for $\mathrm{erg\,K^{-1}}$. A named unit is an entry of the table: a name such as `km/s`, its value in cgs and its dimension. The factor of a named unit is the number by which a value given in it is multiplied to give the value in code units. A relative difference is bounded in terms of $\epsilon = 2^{-52}$, the machine epsilon of double precision. The units rely on the constants and on the standard library alone.

## The code units of a run

<a id="unit01"></a>**UNIT01** `Units` shall take the base units $M_0$, $L_0$ and $T_0$ in cgs as its fields `mass`, `length` and `time`, each 1 by default, so that a run without units of its own computes in cgs. [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units) lets each run choose its code units, from which every other unit derives, so that the values of a problem of the interstellar medium lie near unity and floors and tolerances of fixed size keep their meaning. By default they are those of cgs, under which a problem without physical units, such as a shock tube, runs unchanged. The author chose mass, length and time, from which Athena++ derives every unit and in which its custom system takes them ([Athena 3.1](../../references/athena-synthesis.md#31-configuration-build-and-the-main-loop)), over the length, density and velocity in which option B of B5D4 words the choice, as both span the same systems and the exponents of a dimension then apply to the base units directly ([UNIT03](#unit03)). A run that wants the density $\rho_0$ and the velocity $V_0$ of its flow near unity takes $M_0 = \rho_0 L_0^3$ and $T_0 = L_0/V_0$, as a named system will do for it. As the declaration of [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters), the class holds the parameters of the units of a run in one place, which the parameters read as the table `[units]`.

<a id="unit02"></a>**UNIT02** If a base unit is not a positive and finite number, then `Units` shall refuse it with a `ValueError` that names the field and its value. A unit is a scale, so that zero, a negative number, an infinity or a NaN would turn every conversion of the run into nonsense, which would show far from its cause. Refused as the units are built, the fault shows before any block is built, as [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters) asks of every fault of the parameters.

<a id="unit03"></a>**UNIT03** The code unit of a dimension $(a, b, c, d)$ shall be $M_0^a L_0^b T_0^c$ in cgs, so that temperature keeps the kelvin as its code unit. [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units) derives every other unit from the base units of the run, as Athena++ derives its own from those of mass, length and time ([Athena 3.1](../../references/athena-synthesis.md#31-configuration-build-and-the-main-loop)). Mass, length and time give no scale of temperature, so that its code unit stays the kelvin, as in Athena++. The temperature of a cell, computed from $p/\rho$ with $k_\mathrm{B}$ and a mass in code units, then comes out in kelvin, in which cooling and conduction take it ([topic 2, §2.1](../../topics/02-equations-of-state.md#21-the-ideal-and-the-isothermal-gas)).

## Named units

<a id="unit04"></a>**UNIT04** The table shall hold at least the named units `cm`, `pc`, `s`, `yr`, `Myr`, `cm/s`, `km/s`, `g/cm^3`, `cm^-3`, `K` and `erg/cm^3`, each with its value in cgs and its dimension. [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units) gives stratum 1 a table of the units that a declaration may name, so that inputs and records read in physical units whatever the system of the run. These are the units in which the grid, the floors, cooling, conduction and the production problem are expected to declare their parameters, as the cells of about 2 pc, the velocity of 75 km/s and the coronae of millions of kelvin of the fountain cloud ([topic 34, §2.6](../../topics/34-cold-clouds-and-mixing-layers.md#26-fountain-clouds-through-a-corona)). A number density converts as a unit of $L^{-3}$, while the density that it implies needs the mean mass of a particle, which belongs to the physics. Later briefs add the units that they need, which keeps the requirement.

<a id="unit05"></a>**UNIT05** The named units `pc`, `yr` and `Myr` shall take their values in cgs from `PARSEC` and `JULIAN_YEAR`, a megayear being a million Julian years. The constants hold the values of their sources in one place ([CONST06](constants.md#const06), [CONST07](constants.md#const07)), so that the table repeats no digit that could drift from them.

<a id="unit06"></a>**UNIT06** The factor of a named unit shall be its value in cgs divided by the code unit of its dimension, which `Units.factor` returns for its name. A value given in a named unit, times its factor, is its value in code units, which the parameters compute for every value whose declaration names a unit, while they keep the value as given for the record ([B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units), [B5D3](../../briefs/B05-parameters-and-units.md#b5d3-the-record)).

<a id="unit07"></a>**UNIT07** If a name is not in the table, then `Units.factor` shall refuse it with a `ValueError` that names the units of the table. A misspelt unit in a declaration, such as `km/sec`, would otherwise convert by a wrong factor or by none. Refused when the parameters check the declarations of a run, it fails before any block is built ([B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters)), and the list of the table shows the spelling meant.

## Constants in code units

<a id="unit08"></a>**UNIT08** `Units` shall give Boltzmann's constant, the mass of the proton, the mass of the electron and the atomic mass unit in code units, as its attributes `boltzmann`, `proton_mass`, `electron_mass` and `atomic_mass_unit`, each the constant in cgs divided by the code unit of its dimension. [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units) gives every constant in code units, so that the formulas of cooling and conduction keep their form in the code units of the run, as in Athena++, and every conversion is made once as a run starts. The astronomical constants enter as named units instead ([UNIT05](#unit05)).

## Verification

<a id="unit09"></a>**UNIT09** Under the default base units, every factor of the table shall equal the value of its unit in cgs, and every constant in code units its value in cgs, exactly. Under cgs every code unit is 1, so that each conversion divides by 1 and changes no bit, and a problem without physical units runs as in cgs ([UNIT01](#unit01)). It is the first of the tests of the units against their constants that close stratum 1 ([§3.1 of the overview](../../overview.md#31-infrastructure)).

<a id="unit10"></a>**UNIT10** For base units whose decimal logarithms in cgs lie in $[-30, 75]$ for mass, $[0, 25]$ for length and $[-11, 25]$ for time, the temperature $m_\mathrm{u}p/(\rho k_\mathrm{B})$, computed in code units from a pressure and a density converted by their factors and from the constants in code units, shall equal that computed in cgs, to a relative difference below $k\epsilon$ with $k = 2^5$. Temperature keeps the kelvin in every system ([UNIT03](#unit03)), so that it is the one quantity that must come out the same whatever the base units, and a single computation tries the factors of pressure and density together with $k_\mathrm{B}$ and $m_\mathrm{u}$, as the tests of the units against their constants ask ([§3.1 of the overview](../../overview.md#31-infrastructure)). A mistaken factor, which [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units) warns would err silently in a run, fails here by orders of magnitude. **[GK]** Each factor and the formula round a few times, so that round-off stays below about fifteen times $\epsilon$, which the bound clears. The ranges reach from the units of the laboratory to those of galaxies.
