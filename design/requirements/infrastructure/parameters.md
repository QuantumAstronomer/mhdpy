# Parameters

**Prefix.** PARAM.

**Status.** Agreed on 2026-11-11.

**Briefs.** [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters), [B5D2](../../briefs/B05-parameters-and-units.md#b5d2-the-format-of-the-values) and [B5D3](../../briefs/B05-parameters-and-units.md#b5d3-the-record), with the conversion of [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units).

## Scope

The parameters take the declarations of the modules of a run and the values that a user gives for it, check the values against the declarations, fill the defaults, convert every value whose declaration names a unit into the code units of the run, and give the record of every value in use, as [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters) to [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units) decide. They are the module `mhdpy.infrastructure.parameters`, with the function `read`, which returns a frozen `Parameters`, the function `from_command_line`, and the exception `ParameterError`, a subclass of `ValueError`. The form of a problem and where it places its declaration are left to the brief on problem setups, the launching of a run and the order in which it applies its sources to the brief on the driver, and where the record is kept, and which parameters a restart may change, to the brief on outputs, restarts and analysis. The seeds of random numbers are parameters like any other ([B5D3](../../briefs/B05-parameters-and-units.md#b5d3-the-record)).

A declaration is the frozen dataclass of one module, and its table is the table of TOML that holds its values. A source is the text of the file of TOML of a run or an override, a nested mapping `{table: {name: value}}` from Python or from the command line. A value as given is a value in the type of its field and in the unit that its declaration names, before conversion, and a value in code units is the same after conversion by the units of the run. The record is the text of TOML that holds every value of a run as given. Every fault raises `ParameterError`, whose message names the table, the parameter and the fault. The parameters rely on the units, on `tomllib` and on the rest of the standard library.

## Declarations

<a id="param01"></a>**PARAM01** The reader shall take as a declaration a frozen dataclass whose class variable `table` names its table and whose fields are its parameters, each with its name, type and default, and, in the metadata of the field, its allowed values under the key `allowed` and its unit under the key `unit` where it has them. [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters) declares the parameters of a module in one frozen dataclass of the standard library, whose fields give each its name, type and default, and whose metadata can carry allowed values or a unit, as [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units) has each declaration name its unit. The class variable names the table in one place with the declaration, so that a renamed class leaves the files of a run valid, as the author decided.

<a id="param02"></a>**PARAM02** The reader shall accept fields of the types `bool`, `int`, `float` and `str`, and of tuples of one of them. These are the scalars that TOML holds as such, and its arrays ([B5D2](../../briefs/B05-parameters-and-units.md#b5d2-the-format-of-the-values)). An array becomes a tuple rather than a list, so that an instance of a frozen dataclass cannot be changed through it.

<a id="param03"></a>**PARAM03** If a declaration is not a frozen dataclass, lacks a table or shares it with another, holds a field of another type, names a unit for a field that is neither a float nor a tuple of floats, names a unit that the table of the units does not hold, or has a default that breaks its own type or allowed values, then the reader shall raise `ParameterError`. A fault of a declaration is a fault of the code, which shows before any block is built, as every fault does under [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters). A unit outside the table is refused by `Units.factor` ([UNIT07](units.md#unit07)) and reported as a fault of its declaration. One type of error for every fault lets a driver or a test catch them all, as the author decided.

## Reading

<a id="param04"></a>**PARAM04** `read` shall take the declarations of a run, the text of its file of TOML and any number of overrides, and apply the file over the defaults and each override over the values before it, in the order given. [B5D2](../../briefs/B05-parameters-and-units.md#b5d2-the-format-of-the-values) gives the values of a run in a file of TOML, with one table to each declaration, overridden by values from Python and from the command line, which override those of the file, which override the defaults. B5D2 leaves open which of Python and the command line wins where both set a value, and with the order of the arguments the driver settles it, as the launching of a run is its brief.

<a id="param05"></a>**PARAM05** `from_command_line` shall turn lines of the form `table.name=value` into one override, each line parsed as a line of TOML and applied in its order. [B5D2](../../briefs/B05-parameters-and-units.md#b5d2-the-format-of-the-values) makes an override from the command line a line of TOML itself, which the same reader parses, so that a value from the command line holds the types of TOML as one from the file does. A later line over an earlier one follows the order of [PARAM04](#param04).

<a id="param06"></a>**PARAM06** Where no source gives a value for a parameter, the reader shall take its default. [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters) has the reader fill the defaults, which each declaration states once.

<a id="param07"></a>**PARAM07** The reader shall read the table `units` by the declaration `Units` in every run, before any other and without converting it, and convert every value of the other tables whose declaration names a unit by its factor. Every value whose declaration names a unit converts into the code units of the run ([B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units), [UNIT06](units.md#unit06)), whose base units are themselves parameters in cgs ([UNIT01](units.md#unit01)), so that they are read first and as given. Their fields name their units, `g`, `cm` and `s`, for the record, which the table of the units holds beside those of [UNIT04](units.md#unit04).

<a id="param08"></a>**PARAM08** `Parameters` shall give, for each declaration of the run, a frozen instance whose values are in code units, as `parameters[Hydro]` for the declaration `Hydro`. [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters) returns for each module an instance that cannot be changed, read by attribute, so that strict checking follows every read, a misspelt attribute included. Indexed by its class, the instance keeps its type under strict checking, as the author decided, and its values are those in which the run computes ([B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units)).

<a id="param09"></a>**PARAM09** `Parameters` shall keep every value as given, in the type of Python that its field names, beside its value in code units. [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units) records each parameter in the unit that its declaration names, so that the reader keeps each value both as given and as converted, and a record repeats it exactly. An integer given for a float is kept as a float, and a scalar of NumPy as the type of Python of its field, so that each reads back the same. **[GK]** NumPy 2 represents a float of its own as `np.float64(0.1)`, which is no value of TOML, so that a scalar of NumPy kept as such would spoil the record.

## Faults

<a id="param10"></a>**PARAM10** If a source names a table that no declaration of the run holds, or holds a value outside every table, then the reader shall raise `ParameterError`. Each source may change only declared names ([B5D2](../../briefs/B05-parameters-and-units.md#b5d2-the-format-of-the-values)), as pyro and Athena++ let theirs change only names that they know, so that a misspelt table fails before the run starts instead of leaving its values unread.

<a id="param11"></a>**PARAM11** If a source names a parameter that its declaration does not hold, then the reader shall raise `ParameterError`. [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters) refuses an unknown or misspelt name before any block is built, which a dataclass already does for its constructor, and the reader does for every source.

<a id="param12"></a>**PARAM12** If a value does not fit the type of its field, then the reader shall raise `ParameterError`, where an integer of Python or of NumPy fits an `int`, such an integer or a float of Python or of NumPy of up to 64 bits fits a `float`, a boolean of Python or of NumPy fits a `bool`, a string fits a `str`, and an array whose elements each fit fits a tuple. TOML tells an integer from a float, so that `nscalars = 1.0` fails as the wrong type ([B5D2](../../briefs/B05-parameters-and-units.md#b5d2-the-format-of-the-values)). **[GK]** The typing of Python accepts an integer where a float is declared (PEP 484), so that `gamma = 2` stands, while `bool` is a subclass of `int`, so that `true` would pass for an integer unless refused, as it is here. Values computed with NumPy in a problem written in Python arrive as its scalars, of which only `np.float64` derives from a type of Python, and the author decided to admit the others, which would otherwise be refused without a fault. A float of `np.longdouble`, which holds more than 64 bits on the development machine, and a complex number stay refused, as no float of Python holds them exactly.

<a id="param13"></a>**PARAM13** If a value is not among the allowed values of its field, then the reader shall raise `ParameterError`. [B5D1](../../briefs/B05-parameters-and-units.md#b5d1-the-declaration-of-parameters) declares allowed values where a parameter is limited, as for the sizes on which the loops of a kernel depend, for which a size without a compiled version must fail at once ([B4D3](../../briefs/B04-packaging.md#b4d3-when-the-physics-is-chosen)).

<a id="param14"></a>**PARAM14** If the text of a file is not TOML, or a line of the command line does not set one parameter of one table in TOML, then the reader or `from_command_line` shall raise `ParameterError`, naming the line. A malformed input would otherwise surface as an error of `tomllib` without the place that a user must change, or set something other than a parameter ([B5D2](../../briefs/B05-parameters-and-units.md#b5d2-the-format-of-the-values)).

## The record

<a id="param15"></a>**PARAM15** `Parameters.record` shall return one text of TOML that holds a table for each declaration of the run and in it every parameter with its value as given, defaults included, in the order of the declarations, `units` first, and of their fields. [B5D3](../../briefs/B05-parameters-and-units.md#b5d3-the-record) records every value in use as one file of inputs, so that the record alone gives a later run the same values, even after a default has changed in the code. The driver writes it as the run starts, before its first step, so that a run that fails still leaves it, and the brief on outputs decides where it is kept. A fixed order makes the records of two runs comparable line by line.

<a id="param16"></a>**PARAM16** In the record, each value whose declaration names a unit shall be followed by a comment that names the unit. [B5D3](../../briefs/B05-parameters-and-units.md#b5d3-the-record), as revised after [B5D4](../../briefs/B05-parameters-and-units.md#b5d4-the-system-of-units), names the unit of each value in a comment taken from its declaration, so that the record reads in physical units. A reader of TOML passes over comments, so that the record still reads back as inputs.

<a id="param17"></a>**PARAM17** The record shall write each float by its `repr`, each integer in decimal, each boolean as `true` or `false`, each string as a basic string of TOML with its escapes, and each tuple as an array. **[GK]** A float written as Python represents it, by the shortest string that reads back to it, returns exactly ([B5D3](../../briefs/B05-parameters-and-units.md#b5d3-the-record)), and TOML reads `inf`, `-inf` and `nan` as Python writes them. The representation of a string by Python is not a string of TOML, so that strings need escapes of their own. The writer is the short writer of mhdpy that [B5D2](../../briefs/B05-parameters-and-units.md#b5d2-the-format-of-the-values) chose over a further dependency.

## Verification

<a id="param18"></a>**PARAM18** When the record of a run is read as the file of a run with the same declarations and no overrides, the reader shall give every value as given and in code units exactly as before, the floats `-0.0`, `inf`, `-inf`, `nan`, the smallest subnormal and `0.1` among them, and strings with quotes, backslashes and line breaks. It is the test of a record that gives back every value of its run, which closes stratum 1 with the tests of defaults, overrides and unknown names of [PARAM04](#param04) to [PARAM14](#param14) ([§3.1 of the overview](../../overview.md#31-infrastructure)). Exactly means equal, with every NaN read back as a NaN and `-0.0` with its sign.
