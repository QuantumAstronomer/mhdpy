# Changelog

All notable changes to mhdpy are recorded here.

## Unreleased

- Project set up according to decision brief D01: src layout, uv with uv_build, ruff, pyright, pytest and continuous integration on GitHub Actions.
- Test setup according to decision brief D02: a `test` extra (pytest, Hypothesis, pytest-cov), a fast and a full test tier selected with `MHDPY_TEST_TIER`, 100 % line and branch coverage enforced in CI on the combined results of all test jobs, and a weekly workflow for the full tier.
- Build setup according to decision brief D04: meson-python with Cython kernels in pure Python mode, compiled by default and run uncompiled with `MHDPY_KERNELS=uncompiled` (both in CI, with coverage combined), and kernels typed for pyright through `.pyi` stubs.
- Requirements documents per layer (`docs/requirements/`), starting with the unit system (UNI01–UNI18), and the first part of the unit system in `mhdpy.foundation.units`: code units, units from dimensions, named units and their labels, conversions of numbers and arrays with exact round trips, the magnetic field with the factor $4\pi$ absorbed, and temperature conversions through the mean molecular weight, with an optional default (UNI01–UNI09). Physical constants and astronomical units in `mhdpy.foundation.constants` (CODATA 2022, AME 2020, IAU 2012/2015), each the double nearest to its published or derived value, and physical constants in code units through `UnitSystem.constant` (UNI10–UNI11). Unit systems cannot be changed once created, compare by their defining values, and convert to and from a record of plain values that is exact bit for bit and names the sources of the constants (UNI12–UNI14). The unit system depends on nothing beyond NumPy (UNI18); the requirements on simulations without a unit system (UNI15–UNI17) are tested once the driver exists. NumPy is the first runtime dependency.
- Task automation according to decision brief D16: `uv run nox` runs every check of a CI test job (formatting, linting, type checking, the tests with the kernels compiled and uncompiled, and their combined coverage), and CI runs the same sessions.
- A README per layer of the package, made of the docstrings of the layer and its modules: written with `uv run nox -s readmes`, and checked against the docstrings by `uv run nox` and CI. The docstrings of the foundation layer, the unit system and the constants now describe their place in mhdpy in full.
- Values with a unit (UNI19–UNI20): `parse` in `mhdpy.foundation.notation` reads a string such as `"100 pc"` or `"1e-27 g cm^-3"` in the notation of the labels, with the cgs symbols of the labels and the astronomical units of the constants, and `UnitSystem.to_code_units` converts it to code units for a named unit or for given dimensions, refusing a value of other dimensions. The magnetic field converts with its named unit, the factor $\sqrt{4\pi}$ included, and a temperature stays in kelvin. The notation, the symbols with their dimensions, the labels of the named units and the reader, needs nothing beyond the standard library, so that the parameters can check units without NumPy (UNI18); the values of the symbols in cgs stay with the unit system.
