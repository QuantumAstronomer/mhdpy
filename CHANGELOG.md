# Changelog

All notable changes to mhdpy are recorded here.

## Unreleased

- Project set up according to decision brief D01: src layout, uv with uv_build, ruff, pyright, pytest and continuous integration on GitHub Actions.
- Test setup according to decision brief D02: a `test` extra (pytest, Hypothesis, pytest-cov), a fast and a full test tier selected with `MHDPY_TEST_TIER`, 100 % line and branch coverage enforced in CI on the combined results of all test jobs, and a weekly workflow for the full tier.
- Build setup according to decision brief D04: meson-python with Cython kernels in pure Python mode, compiled by default and run uncompiled with `MHDPY_KERNELS=uncompiled` (both in CI, with coverage combined), and kernels typed for pyright through `.pyi` stubs.
- Requirements documents per layer (`docs/requirements/`), starting with the unit system (UNI01–UNI18), and the first part of the unit system in `mhdpy.foundation.units`: code units, units from dimensions, named units and their labels, conversions of numbers and arrays with exact round trips, the magnetic field with the factor $4\pi$ absorbed, and temperature conversions through the mean molecular weight, with an optional default (UNI01–UNI09). Physical constants and astronomical units in `mhdpy.foundation.units.constants` (CODATA 2022, AME 2020, IAU 2012/2015), each the double nearest to its published or derived value, and physical constants in code units through `UnitSystem.constant` (UNI10–UNI11). Unit systems cannot be changed once created, compare by their defining values, and convert to and from a record of plain values that is exact bit for bit and names the sources of the constants (UNI12–UNI14). The unit system depends on nothing beyond NumPy (UNI18); the requirements on simulations without a unit system (UNI15–UNI17) are tested once the driver exists. NumPy is the first runtime dependency.
- Task automation according to decision brief D16: `uv run nox` runs every check of a CI test job (formatting, linting, type checking, the tests with the kernels compiled and uncompiled, and their combined coverage), and CI runs the same sessions.
- A README per layer of the package, made of the docstrings of the layer and its modules: written with `uv run nox -s readmes`, and checked against the docstrings by `uv run nox` and CI. The docstrings of the foundation layer, the unit system and the constants now describe their place in mhdpy in full.
- Values with a unit (UNI19–UNI20): `parse` in `mhdpy.foundation.units.notation` reads a string such as `"100 pc"` or `"1e-27 g cm^-3"` in the notation of the labels, with the cgs symbols of the labels and the astronomical units of the constants, and `UnitSystem.to_code_units` converts it to code units for a named unit or for given dimensions, refusing a value of other dimensions. The magnetic field converts with its named unit, the factor $\sqrt{4\pi}$ included, and a temperature stays in kelvin. The notation, the symbols with their dimensions, the labels of the named units and the reader, needs nothing beyond the standard library, so that the parameters can check units without NumPy (UNI18); the values of the symbols in cgs stay with the unit system.
- Each component of a layer is a package of its own, with its tests in a `tests/` package next to its modules (D01.4): the unit system in `mhdpy.foundation.units`, with the modules `system` (`UnitSystem`), `constants` and `notation`, and the parameters in `mhdpy.foundation.parameters`, whose requirements (PAR01–PAR23) are being turned into tests. A layer's README has a section per component.
- The switch between compiled and uncompiled kernels and the first kernel move from the top of the package into a component of their own, `mhdpy.foundation.kernels`, with the modules `mode` and `backend` and their tests next to them; the top of the package keeps only what Python, pytest and meson need there.
- Declarations of parameters in `mhdpy.foundation.parameters.declarations` (PAR01–PAR05): a module declares each parameter as a `Parameter`, with its name, type, default, documentation, unit, an optional `Check` and its restart behaviour, and the parameters of a run are gathered as one `Declarations`. A declaration is refused as soon as it is made if it is incomplete, if its name is not dotted lowercase identifiers, if its type is not bool, int, float, str or a list of one, if its default does not fit its type, unit or check, or if a number has no valid unit; a set is refused if a name is declared twice or is the start of another. The units of declarations are checked through the notation, without NumPy, with `notation.unit_dimensions`, which the conversion of values with a unit uses as well.
- Resolution of parameters in `mhdpy.foundation.parameters.resolution` (PAR06–PAR10): `resolve` gives the `Parameters` of a run, a read-only mapping from each name to its value, from the declared defaults, a TOML parameter file and overrides, each layer replacing the one below. Tables, dotted keys and nested dictionaries give the same names. Overrides are a dictionary or `name=value` strings, whose values are read as TOML, or as a string where they are not valid TOML. A value with a unit, such as `"100 pc"`, is converted to code units by the unit system passed as `units`, which the parameters only ask for its conversion (`UnitConverter`), so that they never import NumPy. An invalid file is refused with its name and the position of the error. A malformed override, a value with a unit without a unit system, for a dimensionless parameter, or with other dimensions than the parameter's, is refused, naming the parameter. Each value records its `Origin`: its source, the file by name, and the value as given.
- Checks of the resolved values (PAR11–PAR14): every mistake in the values of a run is reported at once, before the run starts, as one `ParameterError`, whose `mistakes` each give the name, the `Origin` of the value and a message. A name that is not declared is refused with the closest declared name as a suggestion. A value must be of its parameter's type, of which only an integer for a float is converted. A value with a unit is refused if it cannot be converted. A value must satisfy its parameter's check, applied in code units and stated in the words of the declaration. The type rules of defaults and values are shared in `mhdpy.foundation.parameters.values`.
- Alternatives and joint checks of parameters (PAR22–PAR23): a quantity that can be given in more than one way is declared as `Alternatives`, named groups of parameters with a default group, such as the ambient density as a mass density or from a number density, a temperature and a metallicity. The values given in the parameter file and the overrides select a group, the default group when none is, and `Parameters.selected` states the selection; values for two groups are refused. A `JointCheck` is a condition on several parameters together, such as an inner radius smaller than the outer one, evaluated on the values in code units once each has passed its own checks. Both kinds of mistake are reported with the others in one `ParameterError`; their `Mistake` has no single origin. The restarts of alternatives wait for those of PAR15–PAR16.
- Access to the resolved parameters and their record (PAR18–PAR19): `Parameters` holds the value of a list parameter as a tuple, and so the value as given in its `Origin`, so that no value can be changed once resolved, not in place, nor through the list it was given as. `Parameters.to_record` gives the `Record` that outputs store and a restart starts from: every value in code units, with lists as lists, and the group selected of each set of alternatives, as a dictionary of plain values that `json.dumps` writes as standard JSON and `json.loads` reads back identically, every float bit for bit.
- Finite floats (PAR24): a float parameter, or an element of a list of floats, refuses a value that is infinite or NaN in code units, so that every value can be recorded in standard JSON. A default is refused when declared, and any other value with the other mistakes in one `ParameterError`, including one that becomes infinite on conversion: `inf` or `nan` in a parameter file, an integer too large for a float, or a value with a unit such as `"1e400 pc"`. The rule is shared as `is_finite` in `mhdpy.foundation.parameters.values`.
- The record as the lowest layer on restart (PAR15): `resolve` takes the `record` of the original run, which replaces the defaults, so that a restart continues with the values the original run used, without a parameter file or a unit system, and with the groups of its alternatives still selected. A value restored from it has the `Origin` `"restart"`, reported as "restart record". A parameter declared since keeps its default and a recorded name no longer declared is ignored, neither refused; a recorded value that its declaration now refuses is refused with the other mistakes.
- What a restart may change (PAR16): the parameter file and the overrides may change only the parameters declared changeable. A new value for a fixed parameter is refused with the other mistakes, stating that the restart file fixes it and at which value; a value equal to the recorded one, compared in code units, is no change, so that the original parameter file can be used unchanged, values with a unit included. Another group of a set of alternatives may be selected on restart only if every parameter of both groups is changeable.
- The changes of a restart (PAR17): `Parameters.changes` lists what a restart changed of the original run, as a read-only `Changes`, for the driver to log and the writers to record: every value and every selected group that differs from the record, each as a `Change` with the recorded and the new one, every parameter missing from the record with the default it took, and every recorded name that was ignored with its recorded value. It is `None` for a run that is not a restart.
