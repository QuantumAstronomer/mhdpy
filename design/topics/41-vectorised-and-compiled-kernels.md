# Vectorised and compiled kernels

## 1. Overview

The kernels of a code, the loops over cells that reconstruct, solve Riemann problems and update, take nearly all of its time, and in Python they run either as vectorised operations of NumPy, which perform each step over whole arrays in C, or as code compiled from Python or another language. On modern processors memory rather than arithmetic limits most such kernels, so that temporary arrays and the layout of the data matter as much as the route. The collection on performance in Python, gathered around the code AGATE of Bard and Dorelli (2026), sets out vectorisation and its temporaries, compilers for Python in Cython, Numba and Pythran, kernels generated or traced by DaCe, GT4Py in Pace and JAX in Veros, wrapped Fortran in PyClaw, one code over several backends in AGATE and Veros, and measured comparisons of these routes and of whole codes against compiled ones. Ulula's cost of a step in NumPy and pyro's kernels in Numba come from the first syntheses (topic 42). The packaging of compiled kernels follows in topic 35, the layout of data in topic 36, and threads, processes and the exchange of ghost cells in topic 42. No reference times one finite-volume kernel of hydrodynamics in every route on one machine.

## 2. Designs

### 2.1 Vectorisation in NumPy

A NumPy array describes a block of memory by its address, the type of its elements, its shape, its strides and flags, so that a slice, a transpose or a reshape is a view that shares the memory of its parent without a copy ([van der Walt, Colbert and Varoquaux](#van-der-walt-et-al-2011) 2011). Vectorisation groups the operations on elements into operations on whole arrays that run in C: a divided difference written with slices offset by one element, `(y[1:] - y[:-1])/(x[1:] - x[:-1])`, runs 100 times faster than a loop of Python on 1000 elements, and broadcasting combines arrays of different shapes through strides of zero. Each operation allocates an array for its result, so that large expressions stream temporaries over the memory bus, and computing into an existing array in place nearly halves the time of a polynomial. Processors now wait for data most of the time, with a latency of memory of about 150 clock steps and a throughput about 25 times too low ([Alted](#alted-2010) 2010). Locality in time and space, blocking into pieces that fit a cache, and libraries such as numexpr, which evaluates expressions blockwise, follow from this, and on several cores, which share one bus, the layout of the data matters still more. **[GK]** Since release 1.13 NumPy elides some temporaries itself, and universal functions write into a given array through their argument `out`.

Detail: [Performance in Python 2.1.1](../references/performance-in-python-synthesis.md#211-the-array-as-a-view-on-memory), [Performance in Python 2.1.2](../references/performance-in-python-synthesis.md#212-vectorisation-and-broadcasting), [Performance in Python 2.1.3](../references/performance-in-python-synthesis.md#213-temporaries-and-the-memory-bus), [Performance in Python 2.1.4](../references/performance-in-python-synthesis.md#214-processors-starved-for-data).

### 2.2 Compilers for Python

Cython extends Python with declarations of C types and compiles modules to C, so that typed loops run at the speed of C, and only the parts that dominate the time need annotations ([Behnel et al.](#behnel-et-al-2011) 2011). Pythran compiles a module of a subset of Python ahead of time into C++, its input staying valid Python, fuses the expressions of NumPy into single loops by expression templates, vectorises them and parallelises them through OpenMP ([Guelton et al.](#guelton-et-al-2015) 2015). Numba compiles single functions just in time through LLVM ([Lam, Pitrou and Seibert](#lam-et-al-2015) 2015, §4).

1. Decorate a function with `@jit`, demanding the mode without Python objects.
2. On the first call with a new combination of argument types, infer the types of all variables locally.
3. Lower the function to LLVM, fusing array expressions such as `a * x + y` into one loop, and compile it to machine code that may run without the global interpreter lock and on several threads.
4. Reuse the compiled version for later calls with the same types.

A function that Numba cannot type falls back silently to an object mode no faster than Python, its optimisations are opaque, and fast code with it calls for a data-oriented design of arrays rather than objects, so that [Kailasa et al.](#kailasa-et-al-2022) (2022) call it a framework rather than a compiler. **[GK]** The Package Index holds no Numba for Python 3.14 on macOS with Intel processors, its last wheel for them, release 0.62.1, supporting Python up to 3.13 ([PyPI](#web-pypi-json)).

Detail: [Performance in Python 2.2.2](../references/performance-in-python-synthesis.md#222-cython), [Performance in Python 2.2.3](../references/performance-in-python-synthesis.md#223-numba), [Performance in Python 2.2.4](../references/performance-in-python-synthesis.md#224-pythran), [Performance in Python 2.2.5](../references/performance-in-python-synthesis.md#225-designing-a-code-with-numba), [Performance in Python 3.4](../references/performance-in-python-synthesis.md#34-numba-a-compiler-built-on-llvm).

### 2.3 Generated and traced kernels

Further routes compile larger units than a function. Data-centric Python translates functions of NumPy into a dataflow graph that makes every movement of data explicit, fuses subgraphs that share an iteration space and generates C++ or CUDA ([Ziogas et al.](#ziogas-et-al-2021) 2021). Pace writes a dynamical core of weather as stencils in the language GT4Py, with indices relative to the point updated, compiled to C++ or CUDA, while a backend in NumPy serves debugging, and compiles the whole loop over the steps through DaCe to remove the cost of calling many small stencils from Python ([Dahm et al.](#dahm-et-al-2023) 2023). Veros traces code written in the interface of NumPy with JAX, which hands it to the compiler XLA; its routines had to become pure functions that return their results, and its tridiagonal solves remain hand-written in Cython and CUDA ([Häfner, Nuterman and Jochum](#hafner-et-al-2021) 2021). PyClaw instead wraps the Fortran kernels of Clawpack with f2py and joins them with NumPy ([Ketcheson et al.](#ketcheson-et-al-2012) 2012). **[GK]** JAX, like Numba, has no wheel for Python 3.14 on macOS with Intel processors.

Detail: [Performance in Python 2.2.6](../references/performance-in-python-synthesis.md#226-data-centric-python), [Performance in Python 2.2.7](../references/performance-in-python-synthesis.md#227-wrapped-fortran-kernels-in-pyclaw), [Performance in Python 2.2.8](../references/performance-in-python-synthesis.md#228-stencils-generated-from-python-in-pace), [Performance in Python 2.2.9](../references/performance-in-python-synthesis.md#229-tracing-by-jax-in-veros).

### 2.4 One code over several backends

AGATE builds its solver from interfaces paired with implementations, from the grid, state and evolver to the reconstruction, the wave speeds, the fluxes, the Riemann solver and the sources, and selects at start-up one of five modes for the work below them ([Bard and Dorelli](#bard-dorelli-2026) 2026, §2.1, §2.3, App. A).

1. Choose the mode: pure Python, NumPy, Numba, CuPy compiling a loop body for the GPU, or a raw kernel in CUDA C.
2. Bind the matching version of every kernel: a loop shared by pure Python and Numba, which iterates over `numba.prange`, a vectorised function, a loop for CuPy and a kernel in CUDA C.
3. Run the algorithm above the interfaces unchanged in every mode.

Veros keeps NumPy and JAX as interchangeable backends, with its original routines in Fortran as a third, compares each subroutine with the Fortran in automated tests, and switches the precision at run time.

Detail: [Performance in Python 2.2.1](../references/performance-in-python-synthesis.md#221-five-modes-of-one-code), [Performance in Python 3.1](../references/performance-in-python-synthesis.md#31-agate-interfaces-and-implementations), [Performance in Python 3.10](../references/performance-in-python-synthesis.md#310-veros-backends-behind-one-code).

## 3. Tests

AGATE times its modes on the Orszag–Tang vortex in ideal MHD on $32^2$ to $2048^2$ cells, on two processors of 64 cores and an A100, against Athena++ on the processors and Cholla on the GPU. Guelton et al. (2015) time an expression of NumPy through each optimisation of Pythran, and four benchmarks in CPython, Cython, PyPy and Pythran. Ziogas et al. (2021) run 52 kernels in NumPy, Numba, Pythran, DaCe and C, among them a Jacobi iteration, the heat equation, horizontal diffusion and vertical advection, on two processors of 16 cores. [Augier et al.](#augier-et-al-2021) (2021) time ten implementations of the N-body problem in Python, C++, Fortran and Julia, with their energy. PyClaw runs the same Fortran kernels as Clawpack on one core, and Pace and Veros run against their models in Fortran on processors and GPUs.

Detail: [Performance in Python 2.3.1](../references/performance-in-python-synthesis.md#231-the-modes-of-agate-on-the-orszagtang-vortex), [Performance in Python 2.3.2](../references/performance-in-python-synthesis.md#232-pythran-against-cpython-cython-pypy-and-numexpr), [Performance in Python 2.3.3](../references/performance-in-python-synthesis.md#233-fifty-two-kernels-in-numpy-numba-pythran-and-dace), [Performance in Python 2.3.4](../references/performance-in-python-synthesis.md#234-compiled-python-on-the-n-body-problem), [Performance in Python 2.7.1](../references/performance-in-python-synthesis.md#271-agate-against-athena-and-cholla), [Performance in Python 2.7.2](../references/performance-in-python-synthesis.md#272-pyclaw-against-clawpack), [Performance in Python 2.7.3](../references/performance-in-python-synthesis.md#273-pace-against-fortran-on-cpu-and-gpu), [Performance in Python 2.7.4](../references/performance-in-python-synthesis.md#274-veros-against-fortran-on-cpu-and-gpu).

## 4. Assessment

On the vortex, pure Python takes 1802 s on $128^2$ cells where NumPy takes 17.6 s, Numba on 16 threads runs 2 to 5 times faster than NumPy on large grids after 13 s of compilation, 1320 s against 7477 s on $1024^2$ cells, and the GPU modes more than 40 times faster than Numba. Athena++ takes 1396 s without threads, as long as Numba on 16 threads, and 214 s on 16 threads, and Cholla runs 10 to 15 per cent faster than AGATE on the GPU. Pythran brings the expression of NumPy from 1.23 ms to 621 μs by fusion, 418 μs by vector instructions and 105 μs on four cores, against 395 μs for numexpr. Over the 52 kernels DaCe runs 10.6 times faster than NumPy in the geometric mean, Numba 4.3 and Pythran 2.7 times, and on the Jacobi iteration in two dimensions Numba gains 18.2, Pythran 21.8 and DaCe 56.2, while on horizontal diffusion they gain 2.9, 1.7 and 39.3. Four versions in Python of the N-body problem run faster than those in C++ and Fortran. PyClaw costs 10 to 60 per cent over Clawpack, Pace runs at 0.21 to 0.27 of the speed of Fortran on processors and 3.2 to 3.6 times faster on GPUs, and vectorised Python is typically 3 to 5 times slower than Fortran, which JAX narrows to 1.4 beyond $10^6$ cells. **[GK]** NumPy alone ranks best in readability and installation, with wheels everywhere, but streams temporaries and stays about five times slower than Athena++ per core on the vortex, so that kernels fused in place gain most. Numba gains a further factor of 2 to 5 and threads at little cost in readability, but breaks the installation by one command on the development machine for Python 3.14, while Cython and Pythran need a compiler only to build wheels and Pythran keeps a fallback in pure Python. DaCe, GT4Py and JAX gain most but add heavy dependencies and models of programming of their own. One interface over several implementations, as in AGATE, keeps the algorithm readable and lets a simple version verify a fast one, at the price of writing each kernel more than once. The references give no rate of cell updates for these kernels, so that mhdpy must measure its own. Open are the default route of the kernels, whether compiled kernels are admitted (topic 35), whether each kernel keeps a second version to check it, and the benchmark by which the rate is tracked (topic 42).
